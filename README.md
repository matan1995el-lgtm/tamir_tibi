# Metaline — אתר ופאנל ניהול

אתר תדמית + פאנל ניהול (Next.js + Supabase) עבור Metaline.

## הרצה מקומית

1. התקנת חבילות:
   ```bash
   npm install
   ```
2. משתני סביבה — העתיקו את `.env.example` לקובץ `.env.local` ומלאו את הערכים האמיתיים מפרויקט ה-Supabase (Project Settings → API):
   ```bash
   cp .env.example .env.local
   ```
   נדרשים:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`

   נדרש **רק** אם רוצים להשתמש בכפתור "הזמנת משתמש" בעמוד משתמשים (ראו סעיף "ניהול משתמשים והרשאות" למטה):
   - `SUPABASE_SERVICE_ROLE_KEY`
3. הרצה:
   ```bash
   npm run dev
   ```
   האתר יעלה בכתובת http://localhost:3000, פאנל הניהול בכתובת http://localhost:3000/admin.

## בדיקות לפני פרסום

```bash
npm run lint    # בדיקת קוד
npm run build   # בנייית production — חייבת לעבור בלי שגיאות
```

## פריסה ל-Vercel

**אפשרות א׳ — חיבור ל-GitHub (מומלץ):**
1. `git push` לריפוזיטורי ב-GitHub.
2. ב-vercel.com → New Project → יבוא הריפו.
3. בהגדרות הפרויקט → Environment Variables, הוסיפו את המשתנים מ-`.env.example` (עם הערכים האמיתיים) עבור Production/Preview/Development — כולל `SUPABASE_SERVICE_ROLE_KEY` אם רוצים שכפתור הזמנת המשתמשים יעבוד גם באתר החי.
4. Deploy. כל push ל-`main` יפרוס גרסה חדשה אוטומטית.

**אפשרות ב׳ — פריסה ישירה מהמחשב (ללא GitHub):**
```bash
npx vercel login
npx vercel --prod
```
ה-CLI ישאל שאלות הגדרה (שם פרויקט וכו׳) ויבקש את משתני הסביבה, או שאפשר להוסיף אותם מראש דרך `vercel env add`.

## מבנה הפרויקט (תמצית)

- `src/app/(site)/` — עמודי האתר הציבורי
- `src/app/admin/` — פאנל הניהול (מאובטח, דורש התחברות)
- `src/lib/site-data.ts` — שליפת תוכן מ-Supabase (עם ISR של 60 שניות)
- `src/proxy.ts` — הגנה על נתיבי `/admin/*` (Next.js 16 שינה את השם מ-`middleware.ts`)
- `supabase/schema.sql` — הסכמה המלאה של מסד הנתונים (מסמך תיעוד — עדכנו אותו אם משנים טבלאות ישירות ב-Supabase)

## מה אפשר לנהל מפאנל הניהול

- **לוח בקרה** — תמונת מצב מהירה (לידים, שירותים, גלריה, המלצות)
- **תוכן עמודים** — כותרות ופסקאות בעמוד הבית / אודות / צור קשר, כולל תמונות
- **עמודים** — יצירה, עריכה ומחיקה של עמודים חדשים לאתר (עורך בלוקים: כותרות, פסקאות, תמונות, כפתורים, רווחים — עם כפתורי הזזה למעלה/למטה לסידור מחדש), כולל שדות SEO לכל עמוד. עמוד מפורסם נגיש מיד בכתובת `/הסלאג-שלו`
- **בלוג** — ניהול מלא של פוסטים: כותרת, תקציר, תמונת נושא, תוכן (אותו עורך בלוקים), קטגוריה, תגיות, שם כותב/ת, ותאריך פרסום. פוסטים מפורסמים מופיעים ב-`/blog` וב-`/blog/הסלאג-שלו`
- **SEO** — כותרת ותיאור מטא ברירת מחדל לכל האתר, תמונת שיתוף (OG) ברירת מחדל, קוד אימות Google Search Console, ומתג "אפשר אינדוקס" (מכבה חיפוש באינטרנט לכל האתר במקרה הצורך — למשל בזמן פיתוח)
- **עיצוב** — גוון צבע ראשי (פלטות מוכנות או צבע מותאם אישית) וגופן לכל האתר הציבורי
- **לידים** — פניות מהאתר, עם חיפוש/סינון/סטטוס/טווח תאריכים, ייצוא ל-CSV, וחיוג/וואטסאפ ישירים לכל ליד
- **שירותים, גלריה, המלצות, מחירון** — הוספה/עריכה/מחיקה/סדר תצוגה/פרסום, כולל העלאת תמונות בגלריה
- **תפריט ניווט** — הקישורים בתפריט העליון של האתר
- **משתמשים** — ניהול הרשאות בסגנון וורדפרס (ראו סעיף הבא) — גלוי רק לבעלים
- **הגדרות** — פרטי העסק (טלפון, כתובת וכו׳) + לוגו מותאם אישית (אופציונלי) — גלוי רק לבעלים

## ניהול משתמשים והרשאות

פאנל הניהול תומך בארבעה תפקידים, בדומה למערכת ההרשאות של וורדפרס:

| תפקיד | גישה |
|---|---|
| **בעלים** (owner) | גישה מלאה לכל מסך בפאנל, כולל הגדרות ומשתמשים |
| **שיווק** (marketing) | תוכן עמודים, עמודים, בלוג, לידים, שירותים, גלריה, המלצות, מחירון |
| **מעצב/ת** (designer) | תוכן עמודים, עמודים, עיצוב, שירותים, גלריה, תפריט ניווט |
| **SEO** (seo) | בלוג, SEO |

ההרשאות אינן רק קוסמטיות בממשק — הן אכופות ברמת מסד הנתונים (Row Level Security ב-Supabase), כך שגם קריאה ישירה ל-API לא תעקוף אותן. רק בעלים יכול לגשת למסך "משתמשים" ולשנות תפקידים או להזמין משתמשים חדשים.

**הזמנת משתמש חדש** נעשית ישירות מתוך פאנל הניהול (עמוד "משתמשים" → הזמנת משתמש): המוזמן/ת מקבל/ת מייל עם קישור להגדרת סיסמה. הפעולה הזו דורשת את משתנה הסביבה `SUPABASE_SERVICE_ROLE_KEY` (ראו הרצה מקומית/פריסה למעלה) — בלעדיו הכפתור יציג הודעת שגיאה ברורה שמסבירה מה חסר. **חשוב:** המפתח הזה הוא "מפתח־על" שעוקף את כל ההרשאות במסד הנתונים — אסור לחשוף אותו לדפדפן ואסור להעלות אותו ל-Git; הוא נדרש רק בצד השרת (ב-`src/app/api/admin/invite-user`). יש להשיג אותו מתוך Supabase Dashboard → Project Settings → API → Project API keys → `service_role`, ולהוסיף אותו הן ל-`.env.local` המקומי והן למשתני הסביבה של הפרויקט ב-Vercel.

הסרת גישה למשתמש (כפתור "הסרה" ליד השורה שלו במסך "משתמשים") חוסמת גישה מיידית — גם אם למשתמש יש חיבור פעיל דרך הדפדפן, הוא ינותק אוטומטית בפעם הבאה שהוא יטען מסך בפאנל.

## איך שינויים בפאנל הניהול מגיעים לאתר החי

כל דף ציבורי (בית, שירותים, גלריה, אודות וכו') קורא את הנתונים ישירות מסופרבייס עם `revalidate = 60` — כלומר Next.js שומר עותק "קפוא" של הדף למשך עד 60 שניות, ואז בפעם הבאה שמישהו נכנס אליו, הוא נבנה מחדש ברקע עם הנתונים העדכניים. בפועל: אחרי שמוסיפים/עורכים/מוחקים שירות (או כל תוכן אחר) בפאנל הניהול, השינוי מופיע באתר הציבורי תוך דקה לכל היותר, בלי צורך בפריסה (deploy) מחדש. רענון ידני (Ctrl+F5) יראה את זה מיידית.

## הערה על תוכן

כל טקסט המסומן ב-`[להשלמה: ...]` הוא מקום שמור לפרט עסקי אמיתי (טלפון, כתובת, שעות פעילות וכו׳) שטרם התקבל מהלקוח — יש להשלים אותו בפאנל הניהול (עמוד "הגדרות") לפני שהאתר עולה לאוויר סופית. תמונות פרויקטים שטרם הועלו מוצגות עם הדמיה מצוירת ותווית "הדמיה" — יש להחליף אותן בתמונות אמיתיות דרך פאנל הניהול → גלריה.
